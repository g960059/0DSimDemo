# Phase 5C-C New-Myocardium Check Plan


> **Some paths below are retired.** This document names tools, tests, and
> artifacts from lanes that were removed from the working tree. They are
> recoverable from git history (`git show <commit>:<path>`); do not read
> them as commands you can run today.

## Context

PR #174 made the Phase 5C-A Land shadow comparator artifact gate pass by
extending the selected thick-sphere-v2 LV calibration-readiness domain down to
30 mL. That gate is still a feedforward shadow replay: it reproduces the fixed
legacy activeStress low-preload period-2 VLV trajectory, prescribes that VLV
trajectory to selected-v2 LV kinematics, and reports Land source-stress
evidence. It deliberately does not satisfy
`alternansPolicy.newMyocardiumCheck.required`.

The next priority is to replace the old active-stress mechanism with Land
evidence enough to test whether a new myocardium path still shows the
low-preload alternans and what pressure morphology it produces. This phase
must avoid two false passes:

1. a feedforward/static harness that is structurally unable to show alternans;
2. a report-only morphology result being read as an official morphology pass.

## Recommended Default

Implement **Phase 5C-C: new-myocardium low-preload check artifact** using a
declared standalone closure:

```text
phase5c-c-standalone-preload-afterload-surrogate-v1
```

This is not ModelCore wiring and not a production closed-loop replacement. It
is a deterministic single-LV surrogate that can generate its own VLV, LVP, QAo,
AoP, stroke work, and branch metrics from selected-v2 mechanics plus a source
stress provider.

The closure is intentionally narrow:

- LV-only cavity-volume state generated by the surrogate, not prescribed from
  the Phase 5C-A legacy VLV trace;
- selected thick-sphere-v2 LV kinematics and Phase 4C passive/generalized-force
  path;
- Land source stress for the new-myocardium run;
- a two-element afterload state derived from the Phase 3C D0 afterload pattern;
- an explicit preload reservoir/source term with fixed low-preload target
  provenance;
- smooth diode-style inlet/outlet conductances for report-only forward/reverse
  flow volumes;
- no TBV projection after initialization;
- no pressure floor;
- no dynamic qDot cap unless it is explicitly introduced as a report-only
  artifact variable with `qDotCapStatus=artifact-only-not-modelcore`;
- no RV, pulmonary, atrial, systemic venous, pericardial, or septal coupling.

The same fixed low-preload protocol boundary as Phase 5C-A remains the owner
protocol context:

- baseline total blood volume 5600 mL;
- delta total blood volume -1250 mL;
- effective target volume 4350 mL;
- `dt=0.001`;
- `sampleHz=120`;
- primary report window of the last four generated beats;
- no return-map acceptance for the primary gate.

The protocol context does not mean the surrogate is physiologically equivalent
to ModelCore. The report must include
`closureEquivalenceToModelCore="not-claimed"`.

## Positive Control

The artifact must include a positive control using the **same surrogate
closure** with a state-dependent legacy activeStress source provider:

```text
sourceProvider=legacy-activeStress-positive-control
```

The positive-control provider must evaluate legacy activeStress as a stress
closure on the surrogate-generated kinematics and activation state. It must not
consume a prerecorded legacy stress, pressure, flow, CO, branch-label, or VLV
time series. Legacy Phase 5C-A outputs may appear only as read-only comparison
evidence outside the generated positive-control trajectory.

The accepted artifact implementation treats `ActiveStressChamberModel` with
`defaultActiveLV` as a read-only equation/parameter source for this provider.
That import is allowed only inside the artifact module; it is not ModelCore,
case, chamber-runtime, official-case, or Workbench wiring. The provider must not
hard-code beat-parity alternans forcing.

The positive-control and Land runs must share identical closure parameters,
initial conditions, dt/sample policy, preload/afterload settings, conductance
settings, and settling policy. Their `closureConfigStableHash` and
`initialStateStableHash` must match; the source provider is the only intended
runtime difference.

That positive control must reproduce period-2 branch behavior under the fixed
low-preload protocol before the Land new-myocardium run can set
`newMyocardiumCheckStatus="performed-be-smoke-not-final"`. Reuse the Phase
5C-A branch acceptance thresholds unless the descriptor explicitly pins stricter
ones:

- `settled=true`;
- `periodBeats=2`;
- `adjacentDelta > 0.1`;
- `periodDelta < 0.05`;
- TBV sanitize/projection equivalent remains clean at `<= 0.05 mL`;
- outlet/inlet reverse-volume equivalent remains non-problematic at
  `<= 0.05 mL`;
- no pressure-floor use;
- finite selected-domain coverage.

The same branch metric definitions and beat window must be applied to the
positive-control and Land runs, including adjacent delta, period delta, EDV,
ESV, stroke volume, QAo peak, AoP peak/mean, LVP peak/min, and stroke work.

If the surrogate cannot reproduce a period-2 positive control, the verifier
must still produce a useful failure report, but the artifact gate must not pass
and the Land run must not be interpreted as evidence that alternans disappeared.
This prevents a vacuous no-alternans result from a harness that cannot express
the legacy bifurcation.

The Phase 5C-C implementation may therefore produce a validation-passing report
with `artifactGate=FAIL` when the faithful positive-control adapter is finite
but settles to period-1. That is a no-go result for interpreting the Land run,
not a final no-alternans claim.

The report should include:

- read-only legacy reproduction evidence from Phase 5C-A;
- selected-v2 LV/RV parameter ids and stable hashes, with RV marked
  `read-only-not-run`;
- Phase 5A BE local-monolithic and Phase 5B SDIRK2 read-only pins;
- closure model id, preload/afterload parameters, initial conditions, and
  deterministic stable hash;
- matching `closureConfigStableHash` and `initialStateStableHash` for the
  positive-control and Land runs;
- `sourceProviderDifferenceOnly=true` if and only if source provider identity is
  the sole generated-run configuration difference;
- `legacyPositiveControlStatus` and its branch metrics;
- `newMyocardiumCheckStatus` distinct from feedforward shadow replay;
- `newMyocardiumCheckRequiredSatisfied=false` for this phase;
- finite state health and selected LV domain coverage;
- branch behavior metrics for period, adjacent delta, period delta, EDV, ESV,
  stroke volume, QAo peak, AoP peak/mean, LVP peak/min, and stroke work;
- event surfaces for outlet/inlet reverse volume, pressure-floor use, TBV
  projection use, source-provider identity, and any artifact-only qDot cap;
- `secondOrderSameProtocolStatus="not-performed"`;
- `phase5BReadOnlySdirk2Status="solver-reference-available-not-same-protocol"`;
- morphology evidence as the named report-only metric set below.

## Report-Only Morphology Evidence

Phase 5C-C must not call or claim the full `collectNormalBaselineGates`
official morphology surface, because that surface expects full ModelCore
closed-loop observables such as PAP, RAP, LAP, atrial PV loops, and valve flows.

Instead, report:

```text
morphologyEvidenceStatus="reported-not-official"
officialMorphologyGateStatus="not-wired"
```

The metric set is:

- `fwhmMs`;
- `timeToPeakMs`;
- `relaxationTauMs`;
- `caToStressPeakDelayMs`;
- `peakStressPa`;
- `strokeWorkJ`;
- pressure morphology metrics limited to generated LVP/AoP/QAo:
  `lvpPeak`, `lvpMin`, `aopPeak`, `aopMean`, `lvpAopPeakGap`,
  `lvpAopPeakLagMs`, `ejectionDurationMs`, `qAoForwardVolumeMl`,
  `qAoReverseVolumeMl`, and `qAoPeak`.

The artifact gate should fail if this metric set is missing or non-finite. It
should not fail merely because the reported morphology is bad.

## Gate Semantics

Use these explicit statuses:

1. `legacyReproductionStatus`
   - read-only Phase 5C-A legacy reproduction remains present and pinned.
2. `legacyPositiveControlStatus`
   - same surrogate closure with legacy activeStress source provider reproduces
     period-2 branch behavior using the pinned thresholds above.
3. `newMyocardiumCheckStatus`
   - may become `performed-be-smoke-not-final` only if the positive control
     passes and the Land run generates its own finite low-preload trajectory.
4. `newMyocardiumCheckRequiredSatisfied`
   - remains `false` in Phase 5C-C because the policy-required final check also
     needs same-protocol second-order interpretation.
5. `secondOrderSameProtocolStatus`
   - remains `not-performed`; Phase 5B pins are not same-protocol agreement.
6. `finalNoAlternansClaim`
   - remains `not-claimed` unconditionally in this phase.

The Phase 5C-C artifact gate may pass when it produces deterministic finite
positive-control and Land-run evidence and correctly reports morphology and
branch behavior. It must not require the Land physiology itself to pass. A
failing morphology or persistent alternans result is useful evidence and should
not be hidden behind a verifier failure.

## Settling And Branch Window

Primary branch evidence uses a deterministic period-aware beat window:

- run the surrogate until either period-1 or period-2 settles under the fixed
  policy, or until the fixed cap is reached;
- report the last four generated beats in all cases;
- if the run does not settle, set
  `newMyocardiumCheckStatus="attempted-not-satisfied"` and
  `settlingStatus="not-settled-reported"`;
- artifact gate may pass for a finite non-settled report only if the positive
  control passed and the non-settling status is explicit;
- no return-map slope is accepted as a pass condition in this phase;
- optional signed return-map diagnostics may be reported as
  `returnMapEvidenceStatus="report-only-not-acceptance"`.

## Required Negative Tests

The validator must fail if:

- the new-myocardium run prescribes or consumes the Phase 5C-A legacy VLV trace;
- the new-myocardium run consumes legacy activeStress time series, branch
  labels, pressure traces, flow traces, CO traces, or `runLowPreloadDebug`
  output outside the read-only legacy reproduction and positive-control
  sections;
- the positive-control source provider consumes prerecorded legacy stress,
  VLV, pressure, flow, CO, or branch-label time series instead of evaluating a
  state-dependent legacy activeStress closure on surrogate-generated state;
- the positive-control and Land runs differ in closure config, initial state,
  dt/sample policy, preload/afterload settings, conductance settings, or
  settling policy;
- the positive-control and Land runs use different branch metric definitions;
- `newMyocardiumCheckStatus` is marked performed without generated
  new-myocardium trajectory evidence;
- `newMyocardiumCheckStatus` is marked performed when
  `legacyPositiveControlStatus` is not a period-2 pass under the pinned
  thresholds;
- `newMyocardiumCheckRequiredSatisfied` is `true`;
- `secondOrderSameProtocolStatus` is anything stronger than `not-performed`;
- Phase 5B SDIRK2 read-only evidence is treated as same-protocol agreement;
- `finalNoAlternansClaim` is anything other than `not-claimed`;
- official morphology pass is claimed before the official gate is explicitly
  wired and scoped;
- ModelCore, chamber runtime, case, official-case, or Workbench wiring is
  introduced in this artifact phase;
- selected-v2 domain coverage or finite health is missing;
- report-only morphology metrics are missing or non-finite;
- Phase 5A/5B read-only pins drift without re-derivation.

## Non-Goals

- Do not replace ModelCore activeStress in production runtime in this phase.
- Do not remove legacy activeStress.
- Do not claim official morphology acceptance.
- Do not claim final robust no-alternans.
- Do not validate calcium-cycling alternans.
- Do not claim RV pressure overload, septal bowing, ventricular
  interdependence, right-heart failure, or TriSeg behavior.
- Do not select the Phase 5.5 atrial bridge.

## Review Questions

1. Are the surrogate closure and legacy activeStress positive-control
   requirements enough to prevent a vacuous no-alternans pass?
2. Is the report-only morphology metric set sufficient for this phase, given
   that full official morphology gates require ModelCore closed-loop surfaces?
3. Should same-protocol SDIRK2 be the next immediate phase if BE smoke appears
   to suppress alternans, or should morphology failures be addressed first?
